# 全面代码审查——结构/质量/Bug/架构/安全

## Goal

对武俱打卡项目进行全面代码审查，覆盖代码结构、代码质量、潜在 Bug、架构合理性、安全漏洞五大维度，输出可操作的修复建议。

## Confirmed Facts

- 项目共 89+ 个源文件（Go + TypeScript/Vue）
- 已有 CODE_REVIEW_REPORT.md 和 REFACTOR_GUIDE.md 记录了部分历史问题
- 已完成的修复：JWT密钥强度检查、内部 API 认证、事务支持、正则注入防护等

## Requirements

### R1: 代码结构审查
- 目录组织是否合理
- 模块间依赖方向是否正确
- 文件大小和拆分是否合理
- 命名一致性

### R2: 代码质量审查
- Go 代码规范（错误处理、日志、常量使用）
- TypeScript/Vue 代码规范（类型安全、组件组织）
- 重复代码
- 测试覆盖

### R3: Bug 发现
- 逻辑错误
- 边界条件
- 并发问题
- 潜在的运行时错误

### R4: 架构审查
- 双服务职责边界
- 层间依赖方向
- 数据流合理性
- 扩展性考量

### R5: 安全审查
- 输入验证
- 认证/授权
- 敏感信息处理
- 常见 Web 漏洞

## Acceptance Criteria

1. 每个维度输出独立的审查报告
2. 问题按严重程度分级（CRITICAL/HIGH/MEDIUM/LOW）
3. 每个问题附有文件路径、行号和修复建议
4. 汇总统计可用
5. 输出审查结果到 .trellis/tasks/07-09-full-code-review/ 目录

## Out of Scope

- 不自动修复发现的问题
- 不涉及部署配置审查（docker-compose, nginx 等已有历史审查）
- 不涉及第三方依赖版本审查
